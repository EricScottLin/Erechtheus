# qqbot_lyric — 歌词接龙

群友发一句歌词，机器人认出是哪首歌，然后**接下一句**。

```
群友A：从前从前有个人爱你很久
小E：但偏偏 风渐渐 把距离吹得好远
     （—— 晴天 - 周杰伦）
群友B：刮风这天我试过握着你手          ← 接过之后的 2 分钟内，接着唱就行
小E：但偏偏雨渐渐大到我看你不见
```

**英文一样支持**（不需要切命令）：

```
群友：if i had my life without you near me
小E：The days would all be empty
     （—— Nothing's Gonna Change My Love for You - George Benson）
群友：hello how are you today           ← 日常英文不会被接
（没反应）
```

## 命令

| 命令 | 权限 | 说明 |
|---|---|---|
| （自动接龙） | — | 群里发歌词即触发（需群管先 `/开启 歌词`） |
| `@机器人 <歌词>` | — | 显式点名：会带上最近几条群聊一起判断 |
| `/歌词 <歌名或歌词片段>` | — | 查歌词：歌名歌手 + 命中行 + 下一句 |
| `/接 <关键词>` | — | 同上（别名） |
| `/歌词 <歌名> <片段>` | — | 歌名不确定时：先按歌名找歌，再定位片段 |
| `/歌词 完整版 <歌名>` | — | 输出整首歌词（最多 40 行） |
| `/本群功能` | 所有人可看 | 查看/开关「歌词接龙」（默认关闭） |

## 怎么判断「这句是不是歌词」（**不依赖 AI**）

判定完全靠本地规则 + 曲库证据，**默认不调用任何模型**：

| 步骤 | 代价 | 说明 |
|---|---|---|
| ① 本地版式 | 0 | 长度/标点/语气/词表/押韵；明显不像直接丢 |
| ② 本地索引 | 0 | 这句在预载曲库里 → 直接接（0.0~0.1 秒） |
| ③ 曲库「按内容搜」 | 0.5~2s | 网易云按内容搜歌名 → 同名多版本取交集 → 逐行比对 |
| ④ 保守复核 | 0 | 用户原句的词/字要基本被命中行覆盖（挡住「只对上半句」） |
| ⑤（可选）模型 | 2~4s | **默认关闭**；只有 `qqbot_lyric_use_llm=true` 且版式分极低时才兜底 |

关键设计（都是实测踩出来的）：

- **「搜到歌」不算证据，「这首歌里有这句」才算**。网易云对任何句子都会硬凑出
  一首歌（「今天下午三点开会大家别迟到」→《周一周一周一》），所以必须回到这首歌
  的歌词里逐行比对，只有真的找到这一句才接。
- **同名多版本取交集**。搜「海阔天空」第 3 首是《兰亭集序》（同名不同歌，但歌词里
  也有这句）；只取第 1 首容易串。改成取前 3 个同名版本，各自对这句打分，
  「最佳 ≥0.75 且次佳 ≥0.6」才信 —— 正版/翻唱/伴奏歌词一致，很自然就满足。
- **保守复核**。`i am on my way home` ↔ 歌词 `I am on my way` 覆盖率只有 5/6，
  不接；而正常歌词片段（含空耳、少标点）覆盖率 ≥0.85。
- **预载曲库**。启动后从网易云热歌榜/飙升榜/新歌榜批量拉歌词（默认 400 首，
  可配），群友发的歌大概率直接命中本地索引，零网络零 AI。

两层，先便宜后贵：

1. **本地版式闸门**（:mod:`gate`）：歌词有规律——不长不短、不一定有标点、
   少用「吗/吧/呢」这类对话语气、歌词语感词密度高、多条连发时常常押韵（用 pypinyin
   近似韵母判断）。明显不像的直接丢掉，**不花模型调用**。
2. **模型确认**（:mod:`judge`）：拿不准的交给模型判「LYRIC / QUOTE / CHAT」，顺带给出
   歌名线索。同一群里 1.5 秒内的多条消息攒成一次请求；批请求失败自动逐条重试。

**模型只给线索，真相以曲库为准**：模型说「这是《晴天》」之后，仍然要去曲库里
把《晴天》的歌词拉下来，逐行比对确认这句真的在里面，再从命中行往后接。

## 曲库（:mod:`library` / :mod:`search`）

主曲库是 [lrclib.net](https://lrclib.net)（免费、无需 key），网易云搜索做兜底——
**实测结论决定了这个架构**：

| 实测现象 | 结论 |
|---|---|
| lrclib 用整句歌词搜（`q=从前从前有个人爱你很久`）返回 **0 条** | lrclib 的 `q=` 是歌名模糊搜索，不能拿歌词搜 |
| `q=小幸运` 有 20 条，但没有一条副歌对得上 | 只能「先猜歌名，再逐行比对」 |
| lrclib 的中文歌词**大多是繁体**（《晴天》《孤勇者》都是） | 歌词行同时索引「原文」和「简体」两份；群友打简体也能命中 |
| 网易云用整句歌词搜能搜到所属歌曲（`我听见雨滴落在青青草地` → 小幸运） | 模型猜不出歌名时，用它按内容兜底 |
| lrclib 没有收录的歌（如张杰《少年中国说》）网易云有 | 网易云查不到时**直接取它的歌词**（`/api/song/lyric`），不依赖 lrclib 收录 |
| 网易云「按内容搜」第一首常是翻唱/remix，甚至会串歌（搜海阔天空第 3 首是《兰亭集序》） | 两阶段：先按内容搜**歌名**，再在歌名上取多首同名版本的歌词**取交集**，一致才用 |
| 网易云歌词开头会混入「作词/编曲/Lyrics by」 | 解析时过滤制作信息行，不会把它们当下一句接出去 |

定位顺序（任何一步命中就返回，不做无谓的重试）：
本地整行精确命中 → 已知歌扫描 → 模型歌名线索 → 用户点名 → 片段显著词 → 网易云兜底。

**按需学习的本地索引**：每见过一首歌，它的每一行都进内存索引并定期落盘
（`data/qqbot_lyric/library.json`）。下次群友发这一句时零网络直接命中。

## 接龙手感（:mod:`relay` / :mod:`state`）

- **连续接窗口**（默认 120 秒）：bot 接过一次后，别人接着唱同一首，直接在同一首歌里
  找位置往下接，不再等模型 —— 更像真的在对唱；
- 窗口外但 15 分钟内出现过的那首，会作为**置顶候选**优先匹配（不轻易换歌）；
- **换歌不会被锁死**：窗口内如果这句在某首歌里找不到，会退回完整判定；
  模型也猜不出时才在这首里再试一次；
- 同一群 45 秒内最多接一次（防止刷屏）；
- 曲库接不上时只说「这句像《X》的歌词，但我没查到下一句」，**不编造**。

## 配置

前缀 `qqbot_lyric_`，完整清单见 `config.py`。常用：

```dotenv
# 开关
qqbot_lyric_enabled=true          # 总开关（按群开关另算，默认关闭）
qqbot_lyric_auto_reply=true       # false = 只识别不接（测试用）
qqbot_lyric_reply_mode=context    # context=接下一句 + 括注歌名；plain=只接下一句
qqbot_lyric_cooldown=45           # 同群两次接龙最小间隔（秒）
qqbot_lyric_relay_window=120      # 连续接窗口（秒）

# 曲库
qqbot_lyric_source=lrclib,netease
qqbot_lyric_netease_fallback=true
qqbot_lyric_timeout_seconds=6

# 判定（留空 = 沿用 qqbot_ai 的模型配置）
qqbot_lyric_use_llm=true
qqbot_lyric_llm_api_base=
qqbot_lyric_llm_api_key=
qqbot_lyric_llm_model=
qqbot_lyric_llm_timeout_seconds=15
qqbot_lyric_llm_min_chars=5
qqbot_lyric_llm_max_chars=60
qqbot_lyric_min_score=0.82

# 免验证（明显像歌词时先用「按内容搜歌」当证据，省一次模型调用）
qqbot_lyric_verify_without_llm=true
qqbot_lyric_quick_verify_timeout=4

# 模型（默认关闭；打开后只在版式分极低时兜底）
qqbot_lyric_use_llm=false
qqbot_lyric_llm_fallback_score=0.3
```

依赖：`pypinyin`（押韵）、`opencc-python-reimplemented`（繁转简）。
两者都是**可缺省**的：没装时插件照常工作，只是押韵判断变粗、繁体歌词匹配变差。

## 实测表现（2026-11-06，纯非 AI，模型调用 0 次）

| 测试集 | 结果 |
|---|---|
| 常见歌词 12 句（中英混杂） | **12/12 接对**，每句 0.7~2.1 秒 |
| 较生僻歌词 18 句 | 13/18 接对（5 句曲库没收录，静默不接） |
| 日常闲聊 48 句（中英混杂） | **0/48 误接** |

漏接的 5 句都是「曲库没有这首歌」或「只发了半句对不上」，**没有一个接错**。
宁可漏接、绝不接错——接错一句在群里比不接尴尬得多。

曲库大小直接决定命中率：预载 400 首热歌后，命中率从 28% 提到 72%，且大半是本地命中。

## 预载曲库（重要）

判定准不准，很大程度取决于本地曲库里有没有这首歌。首次部署后跑一次：

```bash
docker cp scripts/seed_lyrics.py qqbot-nonebot:/tmp/seed_lyrics.py
docker exec -i -w /app qqbot-nonebot python /tmp/seed_lyrics.py --max 600
# 重启让 bot 加载
docker compose restart nonebot
```

- 从网易云热歌榜/飙升榜/新歌榜/原创榜拉歌名，再逐首取歌词，存进
  `data/qqbot_lyric/seeded.json`（约 400~600 首、2 万行）；
- **`seeded.json` 是只读的**：运行中的 bot 只写 `library.json`（按需学习的新歌），
  永远不会覆盖预载内容。这一点是踩坑后专门隔离的 —— 之前预载完会被运行中
  bot 的旧内存快照覆盖回 24 首；
- 想扩大曲库：`--max 1000 --reseed`（会重新拉一遍，耗时约 2 分钟）。

## 排障

1. 群里没反应：先看 `data/qqbot_group/features.json` 里该群 `lyric` 是否为 `true`
   （默认关闭，群管发 `/开启 歌词`）；
2. 看日志：`docker logs qqbot-nonebot | grep qqbot_lyric`
   —— 每接一次会打 `[qqbot_lyric] 群 X 接龙：歌名 - 歌手 第 N 行（方式, score）`；
3. 总是不接：可能版式闸门把它判成「不像歌词」（短于 5 字 / 长于 60 字 / 事务性口语），
   可以直接用 `/歌词 <片段>` 手动查，绕过闸门；
4. 接的歌词是繁体：lrclib 的歌词本身是繁体，接出来保持原样（不做繁简改写）。
